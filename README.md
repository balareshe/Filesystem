# 用户档案系统

AstrBot 插件 — 在 QQ 内管理用户档案，支持 **全局统一存储、跨群互通、域名检测与六维评分**。

📦 GitHub：https://github.com/balareshe/Filesystem

当前版本：**1.7.2**

## 功能

| 命令 | 说明 |
|------|------|
| `/绑定账号` | 绑定 QQ 号创建档案（**仅限群聊**） |
| `/查询档案` | 查询档案（白名单管理员可 @ 查他人） |
| `/绑定网站 域名` | 智能模式：自动抓取网站标题作为名称，类型默认「博客」 |
| `/绑定网站 名称 类型 域名` | 手动指定网站信息 |
| `/更新网站 名称 类型 域名` | 更新已绑定的网站信息 |
| `/解绑网站` | 解绑网站，基础档案保留 |
| `/查询域名 [域名]` | 域名实时信息（存活 / 延迟 / 归属地 / WHOIS） |
| `/查询备案 [域名]` | 查询域名 ICP 备案信息 |
| `/查询证书 [域名]` | 查询域名 SSL 证书信息 |
| `/删除档案 @用户` | 删除用户档案（仅白名单管理员） |
| `/评价` | 六维加权综合评分（百分制 0~100） |
| `/排行` | 查看评分榜 TOP12 |
| `/hda` | 显示所有命令帮助 |

### 查询命令用法

所有查询命令都支持两种方式：不写参数查绑定域名，或直接指定域名。

| 用法 | 说明 |
|:----|:----|
| `/查询域名` | 查询已绑定域名的存活、延迟、归属地、WHOIS |
| `/查询域名 域名` | 查询指定域名 |
| `/查询备案` / `/查询备案 域名` | ICP 备案（需配置 ICP 密钥） |
| `/查询证书` / `/查询证书 域名` | SSL 证书（**无需密钥**，直连 443 读取） |
| `/评价` | 对已绑定网站做六维评分 |
| `/排行` | 查看评分排行榜 TOP12 |

## 特点

### 全局档案
档案跟随 QQ 号，**不区分群**。在任意群绑定后，所有群都能查到同一份档案。

### 跨群互通
- 在 A 群 `/绑定账号` → B 群也能 `/查询档案`
- 在 B 群 `/绑定网站` → A 群也能看到网站信息
- 修改、解绑等操作全局生效

### 私聊支持
除 `/绑定账号` 外，其他所有命令均支持私聊使用（私聊时会按"上次所在群"推断归属）。

### 域名查询
`/查询域名` 可获取域名实时信息：

```text
📋 域名信息
名称：摆烂的小站
类型：博客
域名：example.com
标题：摆烂的小站
状态：200
延迟：318ms
HTTPS：可用（证书有效）
服务器：nginx
IP：1.2.3.4
地区：中国 广东 深圳
注册商：Alibaba Cloud
注册：2023-01-15
到期：2027-01-15
有效期：1年
证书剩余：6个月
特征：gzip · 移动✓ · 安全头3/4
```

- 网站标题、服务器、响应状态、延迟 → 实时抓取
- 服务器地区 → IP 归属地查询（ip-api.com）
- 注册商、注册/过期/更新时间 → WHOIS API（需密钥）
- 证书 → **直连 443 读取，不需要密钥**

结果缓存 10 分钟，避免同一域名被反复探测触发对方限流。

### 智能模式

`/绑定网站 域名` 支持智能识别：自动抓取网站标题作为网站名称、类型默认「博客」。识别失败时按提示改用手动模式。

### 抓取健壮性（v1.6.4 起持续加固）

`/绑定网站 域名` 的智能模式要抓首页标题，下面每一行都是实测踩出来的，不是拍脑袋加的：

| 坑 | 现象 | 修法 |
|---|---|---|
| 显式声明 `br` / `zstd` 但没装解码器 | 服务器回 brotli/zstd 时 aiohttp 直接抛 `Can not decode content-encoding`，整次探测失败 | 不再手写 `Accept-Encoding`，让 aiohttp 按自身能力协商 |
| `StreamReader.read(n)` 提前返回 | chunked 响应上只拿到 **8192 字节**就停，`<title>` 在后面的站永远读不到 | 改用 `iter_chunked` 自己累积，读到 `</head>` 或上限为止 |
| 标题只认 `<title>` | 前端渲染的站（Nuxt/Next）`<title>` 可能很靠后或干脆没有 | 依次兜底 `<title>` → `og:title` → `twitter:title` → `og:site_name` |
| apex 只有前端壳 | `yadelei.top` 返回的是骨架页，`www.yadelei.top` 才有预渲染内容 | apex 抓不到标题时，自动用 `www.` 再试一次 |
| 首页连 og:title 都没有 | 前端渲染站的 `<meta>` 也可能缺失 | 继续兜底 JSON-LD 的 `name`（含 `@graph`）与 `apple-mobile-web-app-title` |
| 整页没有标题 | 首页只是骨架，抓不到任何标题 | 再试 `/rss.xml`、`/feed.xml`、`/atom.xml`、`/feed`，从 feed 的 `<title>` 取站点名 |
| 人机验证拦截 | Cloudflare 等返回挑战页，内容是 `Just a moment...` | 识别挑战页标记后**不用它的标题**，并明确提示"被人机验证拦截" |
| 前端渲染壳 | 页面只有 `__NUXT__` / `__NEXT_DATA__` / `id="app"` 之类骨架 | 标记为"前端渲染"，评分里内容维度记「无数据」而不扣分 |

实测（`/绑定网站 www.yadelei.top`）：修复前直接报「无法自动获取网站名称」，修复后抓到 `烤鸭の博客`。

### 域名规则（重要）
为安全起见，域名会先做归一化与校验：

- 自动转小写、去掉开头的 `www.`、去掉结尾的点 → `Example.com`、`example.com`、`www.example.com` 视为**同一个域名**
- **拒绝 IP 地址**（`127.0.0.1`、`192.168.1.1` 等）
- **拒绝内网/保留域名**（`*.local`、`*.internal`、`*.lan`、`*.test`、`localhost` 等）
- 解析结果落在私网网段的域名同样会被拒绝

这样可以避免有人拿机器人的网络环境去探测内网服务。

### 固定编号
每个用户绑定账号时自动分配全局唯一的编号，后续不会改变（并发绑定也不会撞号）。

## 网站评价（v1.6.0）

`/评价` 的目标是**测得真、看得懂、能照做**，所以做了三件事：

1. 每个维度都必须对应一个**能实测的信号**，不接受"字段存在就得分"
2. 速度用**冷启动多次采样取中位**，不是一次请求就下结论
3. 分数存历史，能看到**比上次好还是差**，并给出具体改进建议

### 权重表（合计 100）

| 维度 | 权重 | 怎么测 | 满分条件 |
|------|-----:|--------|---------|
| 可用性 | 25 | 状态码 + HTTPS 有效性 + 是否错误页伪装 | 2xx、HTTPS 证书有效、页面有真实内容 |
| 内容与工程 | 25 | 见下方 6 个子项 | 6 项全中 |
| SSL 证书 | 20 | 443 直连 / SSL API | 剩余 ≥ 90 天，且 SAN 覆盖本域名 |
| 域名有效期 | 15 | WHOIS | 剩余 ≥ 2 年 |
| 响应速度 | 10 | 冷启动 3 次请求取中位 | ≤ 400ms |
| 域名年龄 | 5 | WHOIS | 注册 ≥ 3 年 |

### 两条「合格线」

有些指标只要达标就算过关，不该因为"不是满分"一直显示成短板：

| 维度 | 合格线（显示 ✅） | 满分线 |
|---|---|---|
| SSL 证书 | 剩余 ≥ **30 天** | 剩余 ≥ **90 天** |
| 域名年龄 | 注册 ≥ **1 年** | 注册 ≥ **3 年** |

低于合格线才计入「待改进」，也只有低于合格线才会给你发续签/续费建议。

**为什么域名年龄只占 5 分**：它对"网站做得好不好"贡献有限，权重给高了会系统性打压新站，只在同分时才有参考意义。

### 「内容与工程」的 6 个子项（共 25 分）

| 子项 | 分值 | 判据 |
|:--|---:|:--|
| 标题 | 6 | 存在、2~60 个字符、且不是错误页 |
| meta description | 5 | 页面有 `<meta name="description">` |
| 移动适配 | 4 | 页面有 `<meta name="viewport">` |
| 传输压缩 | 4 | `Content-Encoding` 含 gzip / br / zstd / deflate |
| 安全响应头 | 3 | HSTS / nosniff / X-Frame-Options / CSP，命中 3 个即满分 |
| HTML 体积 | 3 | ≥ 2KB（过小通常是跳转页或骨架页） |

> 拿不到的子项（例如反向代理吞掉了 `Content-Encoding`）记为「无数据」，**不进分母**，不会被误判成"未压缩"。

### 四条关键规则

1. **动态分母**：维度拿不到数据时，不进分子也不进分母 —— 缺数据不扣分，只有「测到了但差」才扣分。
2. **覆盖率收敛**：只测到一部分指标时，分数按覆盖率向 60 分收敛，避免"只测了个可用性就拿 100 分"。输出里显示 `数据覆盖 82%`。
3. **错误页识别**：返回 200 但标题/极小页面里出现「网站建设中 / 域名未绑定 / 404」等特征时，可用性打 2.5 折、内容维度归零 —— 挂着的站拿不到高分。
4. **趋势对比**：每次评价写入 `_history_{域名}`（保留最近 10 次），下次直接显示 `较上次 ↑0.6（3.6 → 4.2） · 3 天前`。

### 输出示例

手机端（QQ 手机版是**比例字体**，靠空格对齐的表格会全部错位、长行会被强制折行），所以输出改成：

- 一行一个维度，不依赖空格对齐
- 不画 `████░` 进度条（颜色符号已表达档次）
- 每行控制在 ≤34 列（约 17 个汉字），避免折行

```text
📊 网站评价 · 摆烂人生的小站
⭐⭐⭐⭐✨ 94/100
数据覆盖 100%
首次评价，已记录基线

✅ 可用性 25% · 200 · 718ms
✅ 内容与工程 25% · 6/6 项达标
✅ 域名有效期 15% · 9年10个月
✅ SSL 证书 20% · 2个月（80%）
✅ 响应速度 10% · 718ms（90%）
```

没拿满的维度会直接标出百分比，「距满分」再点出最容易补的两项 —— 这样「全绿却不是 100 分」一眼就能看出差在哪。

### 评分结论

| 分数 | 结论 |
|---|---|
> 分数是**百分制**，直接看数字就知道差多少；星级只是把 100 分切成 5 档（每档 20 分）。

| 分数 | 结论 |
|---|---|
| ≥ 90 | 非常优秀的网站 |
| 76 ~ 90 | 整体表现良好 |
| 60 ~ 76 | 中规中矩 |
| 40 ~ 60 | 存在明显短板 |
| < 40 | 状态较差 |

站点**完全无法访问**时直接给 0 分、不入榜、不写历史。

## API 密钥配置

三个密钥都在插件配置里填写，均已开启**密码遮罩**（不会在管理面板明文显示）：

| 配置项 | 用途 | 是否必需 |
|:------|:----|:--------|
| **WHOIS API 密钥** | 注册商 / 注册时间 / 到期时间 | 可选，缺省时相关维度显示"无数据" |
| **SSL API 密钥** | 证书兜底查询 | 可选，直连失败时才用 |
| **ICP 密钥** | `/查询备案` | 可选项，但缺了 `/查询备案` 不可用 |

密钥获取：发邮件至 **bai@umrca.com**。

**申请模板**（复制下面这段，填好发到 `bai@umrca.com`）：

```text
主题：【AstrBot 插件密钥申请】<你的名称> - <WHOIS / SSL / ICP / 全部>

一、名称 / 称呼：
二、联系方式：（用于回传密钥，建议邮箱；也可留 QQ）
三、申请接口：WHOIS / SSL / ICP（可多选，写「全部」也行）
四、用途场景：（例如：个人 AstrBot 机器人自用 / 网站可用性监测 / 学习测试）
五、预计调用频率：（例如：每天 50 次左右）
六、主要查询的域名：（自有域名或公开域名，可留空）
七、是否已有密钥：（否 / 曾申请过，需更换）
```

> 提交后预计 **3 天内**回复。
>
> 密钥请只保存在自己的 `data/config/` 插件配置里，不要贴到群聊、截图或公开仓库。

> ⚠️ 这三个服务是同一作者的第三方自建服务（`whois.blid.top`、`ssl.blid.top`、`icp.blid.top`），不是 AstrBot 官方能力。任一服务下线会直接影响对应命令。密钥以明文保存在 `data/config/` 下的插件配置文件中，请勿外泄。
>
> 另外几条实测结论：
> - **WHOIS 返回的 `contacts` 段可能包含未脱敏的注册人姓名/邮箱**，插件只读取 `registrar` 与 `dates`，**不读取也不展示联系人信息**。
> - **ICP 接口偶发返回与关键词无关的缓存记录**（实测中出现过三次不同域名返回同一条记录，随后恢复正常），插件会校验返回记录的域名与查询域名是否相关，不相关的一律过滤，不会张冠李戴。
> - 三个接口的 UA 都有黑名单，`curl`、`wget`、`python-requests`、`python-urllib` 会被 403；插件已固定使用浏览器 UA。

## 网站类型

`博客` `企业` `个人` `商城` `论坛` `其他`

## 权限

- **普通成员**：绑定账号、查询档案、绑定/更新/解绑网站、查询域名/备案/证书、评价、排行（仅本人）
- **白名单管理员**：删除档案、@ 查他人档案（在插件配置 `admin_ids` 中填写 QQ 号）
- 管理员权限**只认白名单**，群主/群管理员不算

## 数据存储

全部数据在 AstrBot 插件维度的 KV 存储中，按 QQ 号全局存储：

| 键 | 内容 |
|---|---|
| `profile_{QQ号}` | 档案本体（JSON） |
| `_domain_{域名}` | 域名独占锁 |
| `_user_group_{QQ号}` | 最近一次所在群 |
| `_next_profile_id` | 全局编号自增 |
| `_rankings` | 评分榜数据 |

`/删除档案` 会同时清理该用户的域名锁与群记录，不会留下幽灵占用。

### v1.5.0

**评价体系重做**
- 改为 6 维加权（可用性 30 / 域名有效期 20 / SSL 20 / 响应速度 10 / 域名年龄 10 / 内容质量 10）

**正确性与安全**

- `/删除档案` 清理域名锁与群记录

**性能与可观测性**

- 域名探测结果缓存 10 分钟
- 关键失败点写入日志，不再静默 `except: pass`

**文案与配置**
- 修正「智能模式默认类型」帮助文案（博客）
- 修正「删除档案」提示语（白名单管理员）
- 三个密钥开启 `secret` 遮罩；移除 schema 中无效的 `name` 字段
- 版本号改为语义化 `1.5.0`，移除 `metadata.yaml` 中无效的 `logo` 字段（`logo.png` 仍自动生效）
